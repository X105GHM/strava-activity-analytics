# Fitness-Analyse-App (Strava)

Auswertungssoftware, mit der Nutzer ihre eigenen Trainingsziele anzeigen, auswerten und verfolgen können. Strava dient als Datenquelle, die Daten werden abgegriffen und selbst ausgewertet.

## Konzept

- Strava ist ein soziales Netzwerk für Sport (Leuten folgen, Aktivitäten ansehen).
- Datenweg: Uhr / Fahrradcomputer → Garmin App bzw. Apple Health → Strava → diese App
- Erfasste Werte: Geschwindigkeit, Höhenmeter, Leistung, Außentemperatur, Belastung des Körpers
- Übertragen werden Sekundenwerte, daraus werden z. B. Durchschnittsleistungen berechnet.
- Grafische Oberfläche: **Streamlit**

## Geplante Funktionen

| Funktion | Beschreibung |
|---|---|
| Gesamt- und Wochenleistung | statt nur eines Einzelwerts wie in Strava |
| Belastungsanalyse | Auswertung der Körperbelastung |
| Zonen-Einteilung | über Herzfrequenz (u. a. Z2 und Z5) |
| Heatmap | eigene Routen |
| HF vs. Temperatur | Herzfrequenz bei unterschiedlichen Temperaturen |
| Auswertungsebene | persönlich und kontenbasiert |

## Projektziel

- Funktionsumfang der ersten Version festlegen
- Auswertung und Anzeige eigener Ziele inkl. Verfolgung von Trainingszielen
- Dashboard mit allen Daten der einzelnen Nutzer

## Datenquellen

### Strava API (beschlossen)

**Enthaltene Daten**

| Bereich | Inhalt |
|---|---|
| Athlete | Profil, Statistiken |
| Activities (Summary) | Distanz, Zeit, Höhenmeter, Ø/Max-Geschwindigkeit, Ø/Max-HF, Ø-Leistung (nur mit Powermeter) |
| Streams (Sekundenwerte) | GPS-Koordinaten, Herzfrequenz, Leistung, Kadenz, Geschwindigkeit, Höhe |
| Segments / Efforts | Segmentzeiten |
| Routes, Gear | Routen, Ausrüstung (Bike, Schuhe; Gangübersetzung) |
| Clubs | nur Details; Club-Aktivitäten, Mitglieder |

**Regeln und Grenzen (Stand Oktober 2026)**

- Authentifizierung per OAuth 2.0, der Athlet bestätigt die Scopes.
- Neue App startet mit Zugriff für 1 Athleten, Upgrade auf 10 ohne Review möglich. Entwickler im Standard-Tier brauchen ein Strava-Abo.
- Limits bei 10 Athleten: 400 Requests/15 min und 4.000/Tag gesamt, davon 200/15 min und 2.000/Tag für Nicht-Upload-Anfragen. Gilt für die ganze App.
- Webhooks sind vorgeschrieben, um Deautorisierungen mitzubekommen.
- Caching max. 7 Tage, danach ist Speichern eingeschränkt.
- Anzeige der Daten nur für den Nutzer, dem sie gehören (betrifft Gruppenvergleich, Run Clubs, Revier-Spiel).
- Nutzung von API-Daten in KI-Anwendungen ist untersagt.

### Alternative: GPX-Dateien (nicht gewählt)

**Ablauf:** Export (Strava, Garmin, bei alten Daten Strava-Bulk-Export) → Upload in Streamlit → `gpxpy` → `pandas` → Auswertung

- **Enthalten:** Position, Höhe, Zeit; HF, Kadenz, Temperatur über Extensions, je nach Quelle auch Leistung
- **Nicht enthalten:** Gang/Übersetzung sowie fertige Zusammenfassungswerte (Ø-Leistung und Zonen müssen selbst berechnet werden)

| Vorteile | Nachteile |
|---|---|
| keine API-Limits, kein Abo, keine OAuth-Hürde | jede Datei manuell hochladen |
| alles pro Aktivität in einer Datei | keine automatische Synchronisation |
| leicht in Python verarbeitbar | Extensions je nach Gerät/App uneinheitlich |
| Strava-API-Regeln greifen vermutlich nicht (prüfen) | „kontenbasiert“ erfordert eigene Nutzerverwaltung |

**Folgen:** Heatmap, Zonen, HF vs. Temperatur und Wochen-/Gesamtleistung wären auch mit GPX möglich, aber nur für hochgeladene Dateien. Follow-Funktion und Social-Teil entfallen.
